# سامانه تبدیل شماره کارت به شبا

پروژه‌ای Full-stack برای استعلام شماره شبا از روی شماره کارت بانکی، با استفاده از API زیرین‌هاب (ZarinHub). رابط کاربری با Nuxt.js و بک‌اند با Go پیاده‌سازی شده است. تمرکز پروژه بر تفکیک لایه‌ای، اعتبارسنجی صریح، مدیریت خطای قابل پیش‌بینی و ذخیره‌سازی قابل ممیزی (Audit) است.

## ویژگی‌های اصلی

- **تفکیک لایه‌ای**: جداسازی کامل لایه HTTP، منطق Application، کلاینت سرویس خارجی و Repository از طریق Interface.
- **اعتبارسنجی دو لایه‌ای**: اعتبارسنجی شماره کارت در سمت کلاینت (طول و رقم) و سمت سرور (الگوریتم Luhn).
- **مدیریت خطای پایدار**: نقشه‌برداری از خطاهای سرویس زیرین‌هاب به کدهای خطای داخلی و HTTP Status مناسب.
- **Audit کامل**: ثبت تمام تلاش‌های استعلام (موفق و ناموفق) در SQLite با ماسک کردن شماره کارت.
- **حفاظت از داده‌های حساس**: عدم ذخیره شماره کارت کامل، عدم افشای Credential یا Stack Trace در پاسخ‌ها.
- **رابط کاربری واکنش‌گرا**: Nuxt.js + Vue 3 + Tailwind CSS با پشتیبانی از RTL، اعداد فارسی، و رفتار مناسب موبایل.

## معماری

پروژه بر اساس **Layered Architecture** ساخته شده است. هر لایه وظیفه مشخصی دارد و از لایه‌های دیگر با Interface جدا شده است:

```text
┌─────────────────────────────────────────────────┐
│  Frontend (Nuxt.js + Vue 3 + Tailwind CSS)      │
└──────────────────────┬──────────────────────────┘
                       │ HTTP (JSON)
                       ▼
┌─────────────────────────────────────────────────┐
│  HTTP Handler Layer (net/http)                  │
│  ├─ Parse & Validate Request                    │
│  ├─ Orchestrate Calls                           │
│  └─ Map Errors to HTTP Responses                │
└──────────────────────┬──────────────────────────┘
                       │
        ┌──────────────┴──────────────┐
        ▼                             ▼
┌──────────────────────┐    ┌──────────────────────┐
│  Service Layer       │    │  ZarinHub Client     │
│  ├─ Normalize        │    │  (External Service)  │
│  ├─ Validate (Luhn)  │    │  ├─ Auth             │
│  └─ Mask             │    │  ├─ Token Refresh    │
└──────────────────────┘    │  └─ CardToIban       │
                            └──────────────────────┘
        │
        ▼
┌──────────────────────┐
│  Repository Layer    │
│  ├─ SQLite           │
│  └─ Memory (Test)    │
└──────────────────────┘
```

### تزریق وابستگی

تمام وابستگی‌ها از طریق **Constructor Injection** تزریق می‌شوند:

```go
repo, _ := repository.NewSQLiteRepository(dbPath)
zarinClient := zarinhub.NewService(username, password)
cardHandler := handler.NewCardHandler(zarinClient, repo, logger)
```

هیچ State سراسری قابل تغییر در پروژه وجود ندارد. رابط‌های `ZarinhubClient` و `Repository` به‌صورت Interface تعریف شده‌اند تا تست‌پذیری و قابلیت تعویض‌پذیری حفظ شود.

## قرارداد API داخلی

### Endpoint

```text
POST /api/v1/card-to-iban
```

### Request

| Header | مقدار |
|--------|-------|
| `Content-Type` | `application/json` |

```json
{
  "card_number": "6219861497401835"
}
```

**نکات:**

- `card_number` می‌تواند شامل ارقام فارسی/عربی، فاصله یا خط تیره باشد؛ سمت سرور نرمال‌سازی می‌شود.
- حداکثر حجم بدنه: **۱ مگابایت** (جلوگیری از حملات DoS ساده).

### Response موفق (HTTP 200)

```json
{
  "success": true,
  "iban": "IR120170000000123456789001"
}
```

### Response خطا

```json
{
  "success": false,
  "error": "شماره کارت وارد شده نامعتبر است",
  "code": "VALIDATION_ERROR"
}
```

### کدهای خطای پایدار

| Code | HTTP Status | توضیح |
|------|-------------|-------|
| `VALIDATION_ERROR` | 400 | ورودی نامعتبر (طول، رقم، Luhn) |
| `METHOD_NOT_ALLOWED` | 405 | متد درخواست غیر از POST |
| `EXTERNAL_REJECTED` | 422 | رد درخواست توسط سرویس زیرین‌هاب |
| `EXTERNAL_AUTH_ERROR` | 502 | خطای احراز هویت با سرویس زیرین‌هاب |
| `EXTERNAL_SERVER_ERROR` | 502 | خطای داخلی در سرویس زیرین‌هاب |
| `EXTERNAL_UNAVAILABLE` | 503 | سرویس زیرین‌هاب در دسترس نیست |
| `EXTERNAL_TIMEOUT` | 504 | زمان پاسخ‌گویی سرویس زیرین‌هاب به پایان رسید |

> هیچ Stack Trace، Credential، پاسخ خام سرویس زیرین‌هاب یا شماره کارت کامل در پاسخ‌های API افشا نمی‌شود.

## ذخیره‌سازی و Audit

تمام تلاش‌های استعلام (موفق و ناموفق) در جدول `audit_logs` با ساختار زیر ثبت می‌شوند:

| ستون | نوع | توضیح |
|------|-----|-------|
| `id` | INTEGER | کلید اصلی خودافزا |
| `request_id` | TEXT | شناسه یکتای درخواست (۱۶ کاراکتر hex) |
| `masked_card` | TEXT | شماره کارت ماسک‌شده |
| `status` | TEXT | `SUCCESS` / `VALIDATION_ERROR` / `EXTERNAL_*` |
| `external_http_status` | INTEGER | کد وضعیت HTTP سرویس زیرین‌هاب |
| `external_response` | TEXT | پاسخ کامل JSON سرویس زیرین‌هاب (در صورت دریافت) |
| `error_message` | TEXT | پیام خطای قابل نمایش به کاربر |
| `client_ip` | TEXT | IP کاربر (با احترام به `X-Forwarded-For`) |
| `duration_ms` | INTEGER | مدت پردازش (میلی‌ثانیه) |
| `created_at` | TIMESTAMP | زمان ثبت رکورد |

### ماسک کردن شماره کارت

- برای شماره کارت معتبر (۱۶ رقم): **۶ رقم اول + ۶ ستاره + ۴ رقم آخر** (مثلاً `603799******9999`).
- برای ورودی نامعتبر (طول غیر از ۱۶): **همه ارقام به‌جز ۴ رقم آخر ستاره می‌شوند**.
- شماره کارت کامل **هرگز** ذخیره نمی‌شود.

## امنیت

| اصل | پیاده‌سازی |
|-----|-----------|
| عدم افشای Credential | خواندن از `.env`، عدم لاگ کردن، عدم ارسال در پاسخ |
| عدم افشای Stack Trace | بازگرداندن پیام‌های عمومی به کاربر، لاگ داخلی جداگانه |
| ماسک کردن شماره کارت | در تمام لاگ‌ها و رکوردهای Audit |
| محدودیت حجم بدنه | `MaxBytesReader` با سقف ۱ مگابایت |
| Timeout اتصال خارجی | HTTP Client با Timeout ۱۰ ثانیه |
| Graceful Shutdown | مهلت ۱۰ ثانیه برای اتمام درخواست‌های در حال پردازش |
| CORS | هدرهای CORS در Handler (برای محیط توسعه: `*`؛ در تولید باید محدود شود) |

| متغیر | اجباری | پیش‌فرض | توضیح |

## نحوه اجرا

### پیش‌نیازها

- **Go**: نسخه 1.21 یا بالاتر
- **Node.js**: نسخه 20 یا بالاتر
- **npm**: نسخه 10 یا بالاتر

### ۱. کلون کردن پروژه

```bash
git clone <repository-url>
cd card-to-iban
```

### ۲. راه‌اندازی بک‌اند (Go)

```bash
# کپی فایل محیطی
cp .env.example .env

# ویرایش .env و وارد کردن مقادیر زیرین‌هاب
nano .env

# دانلود وابستگی‌ها
go mod download

go run ./cmd/server
```

سرور روی `http://localhost:8080` بالا می‌آید.

در یک ترمینال جدید:

```bash
cd frontend

# نصب وابستگی‌ها
npm install

# اجرا
npm run dev
```

فرانت‌اند روی `http://localhost:3000` بالا می‌آید.

مرورگر را باز کنید و به آدرس `http://localhost:3000` بروید. شماره کارت ۱۶ رقمی خود را وارد کرده و روی «استعلام شبا» کلیک کنید.

## تصمیم‌های فنی

### ۱. استفاده از SQLite با درایور `modernc.org/sqlite`

**دلیل:** درایور بدون نیاز به CGO، قابل کامپایل روی تمام پلتفرم‌ها بدون وابستگی به کتابخانه‌های C. برای پروژه‌هایی با بار کم تا متوسط (نظیر این تسک) مناسب است.

**Trade-off:** برای بار سنگین‌تر یا نیاز به همزمانی بیشتر در نوشتن، PostgreSQL توصیه می‌شود.

### ۲. Interface برای `ZarinhubClient` و `Repository`

**دلیل:** امکان Mock کردن آسان در تست‌ها، قابلیت تعویض پیاده‌سازی (مثلاً Memory به‌جای SQLite در تست)، و رعایت Dependency Inversion Principle.

### ۳. Context در تمام فراخوانی‌های خارجی

**دلیل:** امکان لغو درخواست توسط کلاینت، Timeout کنترل‌شده، و پیروی از الگوهای idiomatic Go.

### ۴. Timeout ۱۰ ثانیه‌ای برای HTTP Client

**دلیل:** جلوگیری از معطل ماندن درخواست‌ها هنگام بروز مشکل در سرویس زیرین‌هاب.

### ۵. Graceful Shutdown با مهلت ۱۰ ثانیه

**دلیل:** اتمام درخواست‌های در حال پردازش پیش از خاموش شدن سرور.

### ۶. ماسک کردن شماره کارت در تمام لاگ‌ها

**دلیل:** حفاظت از داده‌های بانکی کاربران، مطابق با اصول حفاظت از داده (Data Protection).

### ۷. نقشه‌برداری خطاها به Category

**دلیل:** جدا کردن خطاهای احراز هویت، Timeout، رد درخواست، سرویس در دسترس نبودن، و خطای داخلی. این کار باعث می‌شود کاربر پیام مناسبی ببیند و کد خطای پایدار دریافت کند.

### ۸. Tailwind CSS v4 در فرانت‌اند

**دلیل:** سرعت توسعه، طراحی Responsive، سازگاری با RTL، و حذف نیاز به CSS سفارشی.

### ۹. `$fetch` به‌جای axios در Nuxt

**دلیل:** `$fetch` به‌صورت خودکار در Nuxt در دسترس است، از `ofetch` استفاده می‌کند و مدیریت خطای بهتری دارد.

## فرضیات

1. **الگوریتم Luhn**: فرض شده است که شماره کارت‌های معتبر بانکی ایران از الگوریتم Luhn تبعیت می‌کنند. (چند استثنای نادر نادیده گرفته شده‌اند.)
2. **سرویس زیرین‌هاب**: فرض شده است که سرویس ZarinHub ممکن است گاهی پاسخ غیر-JSON برگرداند (مثلاً صفحات HTML خطا). این حالت به‌عنوان `EXTERNAL_SERVER_ERROR` دسته‌بندی می‌شود.
3. **CORS**: در محیط توسعه، `Access-Control-Allow-Origin: *` تنظیم شده است. در محیط تولید، این مقدار باید به دامنه فرانت‌اند محدود شود.
4. **پایگاه داده SQLite**: برای بار کم تا متوسط مناسب است. برای بار سنگین‌تر، مهاجرت به PostgreSQL توصیه می‌شود.
5. **مدیریت Token**: توکن زیرین‌هاب با استفاده از `refreshToken` تمدید می‌شود. در صورت شکست، از username/password استفاده می‌شود.

## یادداشت‌ها

- **پورت فرانت‌اند**: در صورت اشغال بودن پورت ۳۰۰۰، Nuxt به‌طور خودکار به پورت بعدی (مثلاً ۳۰۰۱) سوئیچ می‌کند.
- **آدرس Endpoint زیرین‌هاب**: در صورت تغییر مسیر `CardToIban` در سرویس ZarinHub، کافی است مقدار `cardToIbanURL` در فایل `internal/zarinhub/client.go` به‌روزرسانی شود.
- **پشتیبانی از ارقام فارسی**: در هر دو سمت (فرانت و بک)، ورودی شامل ارقام فارسی/عربی به‌صورت خودکار نرمال‌سازی می‌شود.
